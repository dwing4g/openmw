Elden Ring asset extraction on Linux/WSL

The supplied Steam installation is packed. The selective reader extracts only
the eleven player animation/event archives and regulation parameters needed by
ELDEN-RING-Combat-Rewrite. It reads the installed game without unpacking into,
patching, or otherwise changing that installation. Generated game data stays
in the recreation's ignored er-files/, src/sim/extracted.rs, assets/*.bin and
OpenMW's ignored components/eldencombat/imported_timings.hpp.

Run from the openmw directory with Python 3.10 or newer. The Python environment
needs cryptography and zstandard. CMake, Ninja, a native x86-64 C++ compiler,
and Git are needed to prepare the Linux reader. CI/eldenring-build-env.sh is
used automatically if the workspace's local validation toolchain exists.

1. Build the reader and fetch the public archive keys:

   bash CI/eldenring-build-asset-decoder.sh

   This fetches pinned source, preserves its licenses, and builds under the
   ignored build-tools-local/elden-assets folder. It uses linoodle to load the
   Oodle DLL from the locally owned game, with no Wine or Windows interop.
   ER_OODLE_DLL is read-only input. The game DLL is neither copied nor packaged.
   Modern regulation data additionally uses the native Python ZSTD reader.

2. Set the native decoder and generate the recreation's data:

   export ER_KRAKEN_LIBRARY="$PWD/build-tools-local/elden-assets/build/liblinoodle.so"
   python3 scripts/unpack_eldenring_assets.py \
     --game-dir '/mnt/c/Program Files (x86)/Steam/steamapps/common/ELDEN RING/Game' \
     --keys-dir "$PWD/build-tools-local/elden-assets/BinderKeys/EldenRing_PC/Key" \
     --generate

   The wrapper sets ER_GAME_DIR and ER_FILES for the generator. The DCX reader
   sets ER_OODLE_DLL to the installed Game/oo2core_6_win64.dll unless explicitly
   overridden. The helper supports the original and current installed game's
   BHD5 RSA headers, per-entry AES ranges, KRAK animation archives and ZSTD
   regulation files. It validates each selected BND4 before writing it.

3. Import the generated timings and reconfigure the OpenMW build:

   python3 scripts/import_eldenring_timings.py \
     ../ELDEN-RING-Combat-Rewrite/src/sim/extracted.rs

   Re-run CMake so OPENMW_ELDENCOMBAT_IMPORTED_TIMINGS is enabled. The Windows build
   helper imports the sibling generated extracted.rs automatically.

The unpacker records source-header and regulation SHA256 digests plus output
sizes/digests in er-files/extraction-manifest.json. This manifest is local.
Audio extraction is optional; no sound banks were extracted in this run.

Validated local outputs, 2026-10-14:
  Eleven player .anibnd.dcx archives and 194 regulation .param files.
  extract.py generated 1,188 ground and 122 airborne source attacks.
  bake_anims.py generated player_anims.bin containing 1,485 skeletal clips.
  importer generated 1,080 OpenMW action definitions, including shield attacks.

The generator omits special-state alternate attack hitboxes (including the
a037 StateInfo=187 variants) so ordinary moves do not count both variants as
separate hits. Two extraction regression fixtures cover conditional variants
and legitimate simultaneous/paired hits. Nine importer fixture groups cover
safe parsing, costs/windows/root motion, airborne attacks and shield grips.

The imported timing table and baked animation bank are consumed by OpenMW.
The renderer retargets the source poses onto Morrowind NPC skeletons. Generated
data is not part of the source licenses and remains local to the user's installation.

Local reader changes: include locale.h, configure the installed DLL through
ER_OODLE_DLL, and export the elden_kraken_decompress C ABI. These are tooling
dependencies only. None is linked into or required to run OpenMW.

The build script can also use already fetched pinned repositories without
network access: ELDEN_ASSET_DECODER_OFFLINE=1 bash CI/eldenring-build-asset-decoder.sh
